# Landing Page Redesign — Design Spec

Date: 2026-07-27

## Goal

Rebuild the marketing landing page (`src/app/(web)/page.tsx` and its section
components, plus the sitewide `Header`/`Footer`) to match the reference
mockup `reference/CA Firm Landing.dc.html` (the "v1" design — the richest of
three alternate mockups in `reference/`, chosen over `v2`/`v3`).

The reference is generated by an external design tool (`<x-dc>`, `support.js`,
`image-slot.js`, Tailwind/GSAP loaded from CDN) and is not runnable as-is —
only its markup structure, Tailwind classes/values, copy, and the bespoke GSAP
behavior in its inline `<script type="text/x-dc">` are of interest. All
design-tool scaffolding is ignored.

## Scope decisions

- **Full replace**, not merge: `page.tsx`'s current sections (`ProblemSection`,
  `ValueProps`) that aren't in the reference are dropped; sections the
  reference has that don't exist today (unified-inbox bento grid, Channels,
  Triage, Reminders, FAQ) are added.
- **Header and Footer are redesigned too** (not just the page body), since the
  reference's nav has a distinctive scroll-shrink animation and different
  links, and its footer uses a light theme vs. the current dark one. The
  existing "Log in" button stays in the Header — it's live functionality the
  reference (a pure marketing mockup) doesn't address.
- **Animations are a fresh, bespoke port of the reference's GSAP behavior**,
  not a reuse of the existing `scroll-reveal.tsx` (`data-reveal`/`data-intro`)
  system. That system becomes fully unused once every consumer is replaced,
  so it is deleted.
- **Images**: the reference's real asset files (`bento-*.webp`,
  `features-bg.jpg`, `cta-bg.jpg`) are copied into `public/images/landing/`
  and used as-is (not placeholders).
- **Product demo**: the existing `product-demo.tsx` is reused unchanged in the
  hero — it's already a faithful TSX port of `reference/CAWorksDemo.jsx`.

## Architecture

### Animation system

New client component `landing-fx.tsx`, mounted once near the top of
`page.tsx` (wrapping the landing sections in a ref'd root), using
`useGSAP`/`ScrollTrigger` (already project dependencies). It scans for
marker attributes on the new markup and drives:

- Masked word-by-word reveal for the hero `h1` and all section `h2[data-rv]`
  headings (split into per-word spans, mask overflow, animate `yPercent`).
- Fade-up reveal for hero intro items (`data-hero-item`) on load, and for
  eyebrows/paragraphs (`data-rv`) on scroll into view.
- Staggered rise for card groups sharing a parent (bento grids, feature rows).
- Continuous parallax on the hero background blob and on bento/section
  images, scrubbed to scroll position.
- Magnetic hover on the primary `cal.com` booking CTAs (button follows cursor
  within a damped radius, springs back on mouse-leave).
- Scroll-velocity-reactive marquee: speeds up/slows/reverses and skews based
  on scroll direction and velocity.
- Respects `prefers-reduced-motion` (disables all of the above) and includes
  a safety fallback that reveals everything if GSAP's ticker never advances.

This mirrors the reference's single `Component` class almost 1:1, just
re-expressed idiomatically for a mounted React client component instead of a
raw DOM-scripted class.

The nav scroll-shrink behavior is **not** part of `landing-fx` — it lives in
`header.tsx` itself as a small local scroll listener, since Header is a
sitewide component rendered on every page, not just the landing page.

## Page section order (final)

1. Header (sitewide, redesigned)
2. Hero (copy, CTAs, avatar/rating row) + `ProductDemo` (reused) + mobile GIF fallback
3. Logo strip (`TrustBar`, restyled)
4. Unified inbox (new: 2-col header, 2×2 image bento, 3-col blurb row)
5. Features (`features-section.tsx` rewrite: bg image, pill row, asymmetric bento, CTA line)
6. Channels (new: compliance board + status timeline mockups, 3-col blurb row)
7. Triage (new: image-left, scorecard mockup + copy)
8. Reminders (new: image-right, reminders-list mockup + copy)
9. How it works (`how-it-works.tsx` rewrite: 4-step card grid)
10. Wall of love (`testimonials.tsx` rewrite: masonry columns, 6 cards)
11. FAQ (new: 3×2 grid, non-collapsible, matching reference)
12. Final CTA (`cta-section.tsx` rewrite: bg image, two CTAs)
13. Marquee (new: scroll-velocity-driven scrolling text)
14. Footer (sitewide, redesigned)

## Styling conventions

- Reuse existing shadcn primitives (`Button` variants, `Badge`, `Card`) and
  existing design tokens (`--primary` `#0464e4` ≈ reference's `#2563EB`,
  `--foreground`, `--muted-foreground`) wherever the reference's intent maps
  cleanly onto them, rather than hardcoding literal reference hex values for
  things that are already semantic tokens in this codebase.
- One-off illustrative colors used only inside the mockup-style cards (status
  dots, chip backgrounds, stat-bar gradients — matching the existing
  `product-demo.tsx` pattern of literal hexes for its own mock UI) are kept as
  literal hexes, since they represent specific illustrated UI, not
  site-wide semantic colors.
- Copy is taken verbatim from the reference (headlines, body copy,
  testimonials, FAQ) since it reflects real product positioning already
  wired to the same `BOOKING_URL`/`APP_NAME` config used elsewhere in the app.
- `BOOKING_URL` and `APP_NAME` continue to come from `src/config/app.tsx`
  rather than being hardcoded.

## Out of scope

- No changes to `/about`, `/pricing`, `/login`, or other routes.
- No changes to the product itself — this is marketing-site markup/copy/
  animation only.
- No new dependencies — `gsap`, `@gsap/react`, `next/image`, existing shadcn
  primitives are sufficient.
